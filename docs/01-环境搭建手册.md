# 01 · 测试环境搭建手册（Docker 容器化）

> 被测系统：`mall` 商城（Spring Boot 3.5.14 + JDK 17）
> 测试环境形态：**全容器化**，一套 compose 拉起「基础设施 + 3 个后端服务 + 后台前端」
> 验证状态：✅ 已在本机（Windows 11 + Docker Desktop 29.9.2 / WSL2）跑通并通过冒烟

| mall-search | `mall-test/mall-search:local` | mall-search | **18081** → 8081 | ES 搜索服务 |
| mall-admin-web | `mall-test/mall-admin-web:local` | mall-admin-web | **8090** → 80 | 后台前端 + 同源代理 |
| MinIO（可选） | `minio/minio` | mall-minio | 9000 / 9001 | `--profile tools` 才启动 |

### 端口为什么不是默认值

| 默认端口 | 实际映射 | 原因 |
|---|---|---|
| MySQL 3306 | **13306** | 本机已安装的 `mysqld`（PID 7160）占用了 3306 |
| mall-admin 8080 | **18080** | 本机另一个项目 `pagewatch-web-1` 容器占用了 8080 |
| mall-search 8081 | **18081** | 与 8080 系列保持一致，避免再次冲突 |

> 这些都是**宿主机映射端口**。容器之间通过服务名 + 容器端口互通（`mysql:3306`、`mall-admin:8080`），
> 所以改宿主机端口不影响应用配置。若换机器需要改端口，只改 `env/.env` 即可。

## 3. 一键搭建（三步）

```powershell
cd C:\path\to\Mall_test\env\scripts

.\pull-images.cmd        # ① 拉取基础镜像（自动走国内加速源）
.\build-images.cmd       # ② Maven 打包 + 构建 4 个应用镜像（约 3-5 分钟）
.\env-up.cmd             # ③ 启动全部容器并等待就绪
.\env-status.cmd         # ④ 巡检：容器状态 + 接口探活 + 资源占用
```

> Windows 默认禁止执行 `.ps1`（`about_Execution_Policies`），因此**统一提供 `.cmd` 包装器**，
> 内部以 `-ExecutionPolicy Bypass` 调用同名 ps1。直接跑 ps1 会报"禁止运行脚本"。

### 各步骤做了什么

**① `pull-images.cmd`**
Docker Hub（`registry-1.docker.io`）在本机**不可直连**，脚本会依次探测
`docker.m.daocloud.io` → `docker.1ms.run` → `dockerproxy.net`，
把 `docker.m.daocloud.io/library/mysql:8.0.36` 拉下来后 `docker tag` 成 `mysql:8.0.36`，
使 compose 文件保持标准镜像名。

**② `build-images.cmd`**
1. 在 `mall-master` 下执行：
   ```powershell
   mvn -B -Dmaven.test.skip=true -Ddocker.skip=true -Dfile.encoding=UTF-8 clean package
   ```
   - `-Ddocker.skip=true` **必须加**：原项目 `pom.xml` 里绑定了 `fabric8:docker-maven-plugin`，
     会在 `package` 阶段连远程 Docker 主机 `192.168.x.x:2375` 构建镜像（该主机不存在，构建必然超时失败）。
   - `-Dmaven.test.skip=true`：跳过测试编译，加快打包。
2. 在 `mall-admin-web-master` 下执行 `npm run build-only`，并注入
   ```powershell
   $env:VITE_BASE_SERVER_URL = "/"
   ```
   即前端所有请求走**相对路径**，由 nginx 同源转发，避免 CORS 与 `localhost` 写死问题。
3. `docker build` 出 4 个镜像：`mall-test/mall-{admin,portal,search,admin-web}:local`。

**③ `env-up.cmd`**
`docker compose up -d` 后调用 `wait-services.ps1` 轮询 4 个就绪探针，最长 5 分钟。

## 4. 数据初始化

- 建库：compose 通过 `MYSQL_DATABASE=mall` 自动创建。
- 建表 + 灌数据：`env/mysql/init/01-mall.sql`（复制自 `mall-master/document/sql/mall.sql`）
  挂载到 `/docker-entrypoint-initdb.d/`，**仅在数据卷为空时执行一次**。
- 实测结果：76 张表、38 条商品、`ums_admin` 内置账号（`admin/macro123`、`macro/macro123` 等）。

**重置数据库**（改坏了 / 要回到初始状态）：

```powershell
cd C:\path\to\Mall_test\env\scripts
.\env-down.cmd -Volumes     # 删除数据卷
.\env-up.cmd                # 重新初始化（会重新导入 mall.sql）
```

> 用例执行会写脏数据（新增用户、订单、购物车），**回归测试前建议 `-Volumes` 重置**，
> 框架层后续用「数据工厂 + 清理 fixture」降低对重置的依赖。

## 7. 已知问题与规避

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker pull` 报 `failed to resolve reference ... registry-1.docker.io` | Docker Hub 不可直连 | 用 `pull-images.cmd` 走 daocloud 加速源，或给 Docker Desktop 配 `registry-mirrors` |
| `./xxx.ps1` 提示"禁止运行脚本" | Windows 执行策略 Restricted | 用同目录 `.cmd` 包装器 |
| ps1 里中文乱码、报 `Unexpected token ')'` | 文件被按 GBK 解析 | 所有 ps1 已存为 **UTF-8 with BOM**，新增脚本请保持该编码 |
| `mvn package` 卡在 `docker:build` 报 192.168.x.x 超时 | fabric8 插件绑定了远程 docker 主机 | 加 `-Ddocker.skip=true` |
| 3306 / 8080 端口被占用 | 本机 MySQL 与 pagewatch 项目占用 | 已分别改映射到 13306 / 18080 |
| 终端里接口返回中文显示为 `æä½æå` | 控制台 GBK 与响应 UTF-8 不一致 | 仅显示问题；会话内执行 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` |
| ES 容器起不来（Linux 宿主） | `vm.max_map_count` 太小 | `sysctl -w vm.max_map_count=262144` |
| mall-admin 启动慢/重启 | JVM 内存限制 512m | 可在 compose 的 `JAVA_OPTS` 调整 |
| MinIO 镜像拉取失败（`denied` / `not found`） | MinIO 官方镜像已从 Docker Hub 下架，国内加速源不同步 | 属可选服务（`--profile tools`），不影响主流程；文件上传类接口用例标记 `skip`，或改指外部 MinIO（`MINIO_IMAGE` 环境变量） |

## 8. 目录结构

```
Mall_test/
├─ env/
│  ├─ docker-compose.yml          # 全栈编排（基础设施 + 应用 + 前端）
│  ├─ .env                        # 端口/密码等变量
│  ├─ docker/
│  │  ├─ Dockerfile.admin|portal|search   # 以 mall 源码为上下文，COPY 已打好 jar
│  │  ├─ Dockerfile.web                   # 以 env/docker 为上下文，COPY web-dist
│  │  ├─ nginx-web.conf                   # 静态站点 + /admin/ 同源代理
│  │  └─ web-dist/                        # 前端构建产物（脚本生成，可删）
│  ├─ mysql/init/01-mall.sql      # 数据库初始化脚本
│  └─ scripts/                    # pull-images / build-images / env-up/down/status / wait-services
├─ docs/                          # 测试文档体系
└─ README.md
```

环境就绪后进入 **pytest + Allure 框架搭建**：
