# 06 · 定时任务与邮件通知

> 目标：让流水线**自己跑起来**（工作日全量、每日含性能），并且**出问题第一时间通知到人**。
> 当前状态：定时触发器与邮件通知均已实测跑通（本地模拟 SMTP 验证收信成功）。

---

## 一、三条流水线（手动 + 两个定时）

| Job | 触发方式 | 默认参数 | 用途 |
|---|---|---|---|
| `mall-cicd` | 手动 | SCOPE=smoke、RUN_UI=true、RUN_PERF=false | 日常快速验证（约 1.5 分钟） |
| `mall-cicd-daily` | **工作日 09:00**（`H 9 * * 1-5`） | SCOPE=full、RUN_UI=true、RUN_PERF=false、**NOTIFY_DAILY=true** | 每天上班前出全量接口 + UI 结果，成功也发汇总邮件 |
| `mall-cicd-nightly` | **每日 02:00**（`H 2 * * *`） | SCOPE=full、RUN_UI=true、**RUN_PERF=true** | 夜间跑全量 + 性能基线，失败才发邮件 |

### cron 说明

- Jenkins 用 5 段 cron：`分 时 日 月 周`；
- `H` 表示「散列」，让多个任务自动错峰（避免整点一起压测）；
- `1-5` 是周一到周五；
- 时区取容器 JVM 时区，compose 里已设置 `-Duser.timezone=Asia/Shanghai` 与 `TZ`。

**改时间**：编辑 `jenkins/create_jobs.py` 里 `JOBS[...]["cron"]`，重新执行：

```powershell
.\.venv\Scripts\python.exe jenkins\create_jobs.py
```

**验证触发器是否生效**：

```powershell
.\.venv\Scripts\python.exe jenkins\cron_selftest.py   # 建一个每 2 分钟的任务，等它自动跑一次再删除
```

## 二、邮件通知

### 2.1 什么时候发

| NOTIFY_MODE / 参数 | 失败 | 成功 |
|---|---|---|
| `auto`（默认） | ✅ 发 | ❌ 不发 |
| `daily` / `NOTIFY_DAILY=true` | ✅ 发 | ✅ 发（每日汇总） |
| `fail-only` | ✅ 发 | ❌ 不发 |

- `mall-cicd-daily` 默认 `NOTIFY_DAILY=true` → 每天一封「成功汇总」；
- `mall-cicd-nightly` 用 `auto` → 只有失败才吵你；
- 通知失败**不会**影响构建结果（`catchError` 包裹）。

### 2.2 需要你提供的信息

| 项 | 说明 | 示例 |
|---|---|---|
| SMTP 主机 | QQ 邮箱 `smtp.qq.com`；163 邮箱 `smtp.163.com` | `smtp.qq.com` |
| 端口 & 加密 | 465 用 `ssl`；587 用 `starttls`；25 用 `none` | `465` / `ssl` |
| 发件账号 | 完整邮箱地址 | `someone@qq.com` |
| **授权码** | 不是登录密码！QQ/163 在「设置 → 账户 → 开启 SMTP 服务」后生成的 16 位码 | `abcd1234efgh5678` |
| 收件人 | 多个用英文逗号分隔 | `qa@x.com,lead@x.com` |

> 拿到后填到 `jenkins/notify.yaml`（已留好位置和注释），或直接设环境变量。
> 生产建议把授权码放到 Jenkins 凭据（Credentials）里，而不是明文写文件——见 2.5。

### 2.3 配置方式

**方式一：配置文件（最快）**　编辑 `jenkins/notify.yaml`：

```yaml
notify_mode: auto
smtp_host: "smtp.qq.com"
smtp_port: 465
smtp_security: ssl
smtp_user: "someone@qq.com"
smtp_pass: "授权码"
mail_from: "someone@qq.com"
mail_to: "qa@example.com,lead@example.com"
```

**方式二：环境变量（优先级更高，适合 CI 注入）**

```powershell
SMTP_HOST / SMTP_PORT / SMTP_SECURITY / SMTP_USER / SMTP_PASS / MAIL_FROM / MAIL_TO / NOTIFY_MODE
```

### 2.4 验证方式

```powershell
# 1) 只打印邮件内容，不真发（检查排版/收件人/状态）
.\.venv\Scripts\python.exe jenkins\notify.py --status FAILURE --build 1 --duration 120 --dry-run

# 2) 在 Jenkins 里触发一封自检邮件（不影响构建结果）
#    任务 mall-cicd → Build with Parameters → NOTIFY_SELFTEST=true
```

邮件内容包含：任务名、构建号、状态、耗时、用例统计（从 junit 汇总）、构建日志链接、Allure 报告链接。

发送记录（含跳过原因）写在 `reports/notify.log`，构建页的 `reports/notify.log` 也会随产物归档。

### 2.5 生产建议：用 Jenkins 凭据而不是明文

1. Jenkins → Manage Credentials → 添加 Username with password（ID 例如 `smtp-cred`）；
2. 在 `Jenkinsfile` 的通知步骤外包一层：

```groovy
withCredentials([usernamePassword(credentialsId: 'smtp-cred', usernameVariable: 'SMTP_USER', passwordVariable: 'SMTP_PASS')]) {
    sh 'python3 jenkins/notify.py ...'
}
```

3. `notify.yaml` 里只留 host/port/to，不写账号密码。

## 四、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `535 Authentication failed` | 用了登录密码而不是**授权码** | 去邮箱设置里重新生成授权码 |
| `Connection refused` / 超时 | 端口被公司网络封禁，或 SSL/端口不匹配 | 465→ssl、587→starttls；换网络或找 IT 放行 |
| 收件人收不到、发件人正常 | 进了垃圾箱 / 企业邮件网关拦截 | 把发件人加白名单；检查 `mail_from` 与登录账号一致 |
| 中文主题乱码 | 主题未做编码 | 已用 `email.header.Header(..., 'utf-8')` 处理 |
| 通知报错但构建成功 | `catchError` 兜底，通知失败不影响构建 | 看 `reports/notify.log` 里的 `error` 字段 |
| 定时没触发 | Jenkins 主机关机 / 任务被禁用 / cron 写错 | 用 `cron_selftest.py` 验证；页面「构建触发器」里看下次执行时间 |
