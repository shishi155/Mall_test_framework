覆盖场景：登录页渲染、错误密码提示、正确登录进首页、未登录访问受保护路由被拦截、商品列表加载、

### UI 阶段的两个发现

**U-01（主要）**：访问未定义路由（如 `/#/pms/product/index`）整页白屏，无 404 兜底 —— router 未配置
`pathMatch` 通配路由。用户输错地址或点旧书签会以为系统挂了。

**U-02（建议）**：前端接口没有统一命名空间前缀，`axios` 直接用空串，业务路径各自为政
（`/admin`、`/product`、`/order`、`/role`…），反向代理必须逐个枚举前缀。本次 UI 冒烟先按 `/admin/` 代理，
商品/订单页直接白屏，nginx 日志里连请求都看不到；改为 `VITE_BASE_SERVER_URL=/api` + nginx `rewrite` 后恢复。

> 这条同时暴露了「接口测试通过 ≠ 前端可用」：接口全绿的情况下，前端仍可能因网关配置整块不可用，
> 这正是 UI 冒烟存在的价值。

## 四、三个值得深挖的缺陷

### 4.1 D-06：下单主流程在多数商品上不可用（阻断级）

`OmsPromotionServiceImpl.calcCartPromotion` 的「无优惠」分支 `handleNoReduce()` **只设置 realStock/reduceAmount，没有设置 price**：

```java
private void handleNoReduce(...) {
    ...
    cartPromotionItem.setPromotionMessage("无优惠");
    cartPromotionItem.setReduceAmount(new BigDecimal(0));
    PmsSkuStock skuStock = getOriginalPrice(promotionProduct, item.getProductSkuId());
    if (skuStock != null) { cartPromotionItem.setRealStock(...); }   // ← 没有 setPrice
    ...
}
```

下游 `OmsPortalOrderServiceImpl.calcCartAmount` 直接 `item.getPrice().multiply(...)` → NPE。
数据侧核对：20 个在售商品中 `promotion_type=0/3/4` 共 18 个，**只有 2 个单品促销商品能下单**。
更糟的是 NPE 被 `/error` 安全拦截（D-02）包装成 `HTTP500 + code401`，前端只会提示“未登录”。

**建议**：`handleNoReduce` 与打折/满减分支补齐 `setPrice`；`/error` 加入安全白名单；异常统一包装。

### 4.2 D-09 / D-10 / D-11：订单模块三处越权

| 场景 | 实测 | 根因推断 |
|---|---|---|
| A 会员删除/取消 B 会员订单 | `code=200`，订单被置为已关闭 | `cancelUserOrder` 未按 `member_id` 过滤 |
| B 会员查询 A 会员订单详情 | `code=200`，返回收货人与金额 | `detail(orderId)` 未校验归属 |
| 已支付订单取消 | `code=200`，status→4 | 未校验订单状态与退款流程 |

**建议**：所有订单操作统一在 SQL 条件中带 `member_id = 当前会员`，状态流转加前置校验；
补一个「越权访问必 403」的回归用例集（已在 `tests/portal/test_portal_order.py` 中存在，修复后自动转 PASS）。

### 4.3 D-15：后台注册接口可直接创建管理员

`secure.ignored.urls` 中包含 `/admin/register`，未登录即可注册后台账号：

```powershell
POST /admin/register {"username":"sec_xxx","password":"Test@1234","nickName":"sec"}
→ {"code":200}
```

新账号默认无角色资源（访问业务接口返回 403，RBAC 本身有效），但**入口开放本身不可接受**：
可批量注册、可占用用户名、可配合爆破使用。

**建议**：移除白名单、改由超管创建；或加邀请码 + 限流。

## 五、结论与发布建议

| 维度 | 结论 |
|---|---|
| 功能完整性 | 主干链路（注册→登录→浏览→加购→确认单→下单→支付→发货）可跑通，**但仅限单品促销商品** |
| 稳定性 | 152 条用例执行 3 轮，结果稳定，无 flaky |
| 安全性 | **不通过**：存在 6 条严重安全问题（越权 2 条、信息泄露 2 条、认证 2 条） |
| 发布建议 | **不建议上线**。至少修复 D-06（主流程）、D-09/D-10/D-11（越权与资金）、D-14/D-15（安全）后再回归 |

### 放行条件（建议）

1. D-06 修复，且「无优惠商品可下单」用例转 PASS；
2. D-09/D-10/D-11 修复，越权用例全部转 PASS；
3. D-14/D-15 修复，SQL 不再外泄、注册接口收敛；
4. P0 用例 100% 通过，P1 用例通过率 ≥ 95%；
5. 回归执行 `pytest -m smoke` 与 `pytest -m security` 全绿。
